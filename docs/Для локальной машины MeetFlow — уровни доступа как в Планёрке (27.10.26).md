# Для локальной машины MeetFlow — уровни доступа как в Планёрке (27.10.26)

Владелица: в MeetFlow сбросились уровни доступа (участник, администратор, суперадмин). Задание:
1. Взять все уровни доступа, как они сейчас распределены в рабочей Планёрке, 1 в 1.
2. Проверить по факту, что у отмеченных сотрудников уровень перенесён.
3. Проверить, что назначение уровня доступа работает.

## Почему сбросилось

У прежнего MeetFlow уровня доступа у сотрудников не было: роль выбиралась в тестовом режиме. Новая «Команда» в виде ERP (перенос экранов 27.10) завела людей проектов записями с ролью «участник». Код ролей рабочий. Ролей просто ещё никто не ставил, поэтому переносим их из Планёрки скриптом.

## Шаги

1. `git pull --no-rebase origin dogonyaem-planerku`. Нужен коммит со скриптом `meetflow/scripts/roli_iz_planerki_2710.py` или выше. Перезапуск через `run_dev`, `/health` 200.
2. **Сухой ход.** Ничего не меняет, базу Планёрки открывает только на чтение:
   `python scripts/roli_iz_planerki_2710.py --planerka-db <рабочая app.db Планёрки> --meetflow-db <рабочая meetflow.db>`
   В консоль выводятся числа: сменить / завести / так же / двойники / только в MeetFlow. Подробная таблица с ФИО ложится рядом с базой MeetFlow, вне git.
3. **Применить** — тем же вызовом с `--apply`. Копия базы делается сама: `meetflow.db.до-ролей-2710`.
   Правила скрипта:
   - роль — как в Планёрке, ФИО сравниваются без учёта «е/ё»;
   - человек Планёрки с ролью выше участника, которого нет в «Команде» MeetFlow, заводится без логина;
   - внешние остаются участниками;
   - двойники по ФИО не трогаются;
   - логины и пароли не переносятся.
4. **Проверка по факту, на экране.** Суперадмином открыть «Команду» MeetFlow. По каждому человеку, у которого в Планёрке роль выше участника, сверить три вещи: роль в Планёрке («Команда» Планёрки), роль в «Команде» MeetFlow и роль в списке «Вы работаете как». Таблицу «ФИО — Планёрка — MeetFlow на экране — сходится» положить в `P:\Technical\AI Projects\MeetFlow\Tests\Роли (27.10.2026)\` — ФИО только там. В отчёт в git — только числа: сколько сверено, сколько сошлось, расхождения ролями без ФИО.
5. **Назначение уровня доступа.** На одном тестовом человеке без логина, потом вернуть как было:
   - суперадмином: участник → администратор → директор → участник; каждый раз роль на экране и строка в «Параметрах системы → Системные сообщения» («Назначена роль: …»);
   - администратором (в тестовом режиме выбрать администратора в «Вы работаете как»): назначить администратора — ожидается отказ «только суперадмин»;
   - понизить последнего суперадмина — ожидается отказ «нельзя понизить последнего»;
   - внешнему поставить роль выше участника — ожидается отказ.
6. Доступ с логином и временным паролем («Выдать доступ») **не выдавать** — только по слову владелицы. Пароли в отчёт и чат не писать.
