# Сверка ERP → MeetFlow 1 в 1 (27.10.2026)

Опись до переноса. Задание владелицы 27.10.2026 по снимкам: «пройтись по всем окнам, всему функционалу, каждое
действие, какой есть в ERP, и перенести в MeetFlow». Образец — актуальный main Проекта ERP (`webapp/frontend/`,
17 файлов, около 11 500 строк), MeetFlow — ветка `dogonyaem-planerku` на `b2ae21e`.

## Как снята опись

Экраны — по маршрутам `nav.js` и `app.js` ERP под тремя ролями: участник, администратор проекта, суперадминистратор.
Подписи кнопок, ссылок, заголовков, колонок, полей и окон подтверждения выбраны из фронта ERP скриптом
(`<button>`, `<a>`, `<h1–3>`, `<th>`, `placeholder`, `confirmDialog`), с привязкой к функции экрана. Колонка
«MeetFlow» — есть ли та же подпись в нынешнем фронте MeetFlow (`web/static/`). Сверка по подписи мягкая: «Дата»
или «Протокол» находятся в MeetFlow где угодно, поэтому «есть так же» по таблице — верхняя оценка; по смыслу ниже,
см. раздел 1. Подписи, собранные в шаблоне из переменных, скрипт не видит — их состав взят чтением, раздел 1.

Обращения к API — все адреса, по которым ходит фронт ERP (`api()`, `fetch()`, `входЗапрос()`), с методом. Колонка
«MeetFlow» — есть ли тот же адрес у сервера MeetFlow. Пути ERP лежат в корне (`/meetings`, `/tasks`), у MeetFlow —
под `/api/projects/{pid}/…`: совпадений по адресу нет ни одного, по смыслу часть есть (раздел 2).

Итог: элементов экрана 328, из них подпись есть в MeetFlow у 136 (41 %); адресов API 123 (плюс 9 адресов «Моделей»,
собранных от общей основы), у MeetFlow по тому же адресу — 0, по смыслу — около 40.

## 2. Подход к переносу

«1 в 1» — тот же фронт: файлы ERP переносятся в `meetflow/web/static/` целиком (разметка, подписи, классы, CSS,
светлая тема), сервер MeetFlow отвечает на те же адреса тем же видом ответа поверх своего ядра и своей базы
(`meetflow/web/erp/`). Допустимых отличий два: многопроектность (выбор проекта, «Все проекты», шапка «Проект —
название» / «Все проекты компании») и папки-приёмники по проектам. Любое другое отличие — строкой в отчёте с причиной.
