# Для локальной машины MeetFlow — папка-приёмник не забирает записи, срочно (27.10.26)

Владелица: две записи лежат в папке, MeetFlow не забрал ни одной, в «Мониторинге» — «Папка-приёмник · MeetFlow — нет … поток завис». Эта записка — **первой**, раньше «наблюдения» и «решений 27.10». Перезапуск разрешён: записи не забраны, в обработке ничего не теряется.

## Причина по коду

Обход папки идёт в одном потоке. После приёма расшифровки с автозапуском проход **ждал конца сборки до 4 часов** (`q.wait`, таймаут `4 * 3600`). Сборка, вставшая в очереди, держала весь забор. Так бывает в трёх случаях:
- повтор после проходящего сбоя: через 10 минут, затем через час;
- чужая строка «идёт» в `build_queue`;
- зависший вызов модели.

Новые файлы при этом не брались, а время прохода не обновлялось — отсюда «завис». Распознавание записи — тоже внутри прохода, у вызова точки «Транс» таймаут тоже 4 часа.

## Исправлено в коде (ветка `dogonyaem-planerku`)

- `dbc24a5`: у прохода пульс, в «Мониторинге» видно «идёт проход: шаг, файл, N мин». «Проход стоит» — только если шаг не двигается дольше 30 минут.
- Новый коммит: проход ждёт автосборку не дольше 60 с (`MEETFLOW_WATCH_AUTORUN_WAIT_SEC`). Дальше сборка идёт в очереди сама, проход забирает следующие файлы. Итог «остановлено по пределу» — файл в «остановлено» — подбирает следующий проход. Тесты: 911 прошли.
