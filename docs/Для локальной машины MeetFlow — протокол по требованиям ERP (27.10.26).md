## 1. Развернуть

1. `git pull --no-rebase origin dogonyaem-planerku`, убедиться, что `git log -1` не раньше `2de2f57`.
2. Перезапуск только через `scripts\run_dev.ps1` (как обычно, тема и порт прежние). Перед перезапуском — очередь сборок
   пуста, в папке-приёмнике нет файла в распознавании (`GET /api/monitoring/intake`: `scan_in_progress: false`).
3. `/health` — 200. В базе сама добавится колонка `meetings.project_pending` (недостающие колонки добавляются при старте).
4. Новое после перезапуска: при падении процесса на уровне C трасса всех потоков пишется в `data\logs\server_crash.log`
   рядом с базой. Если файл появится — приложить его к отчёту.

## 2. Перенести встречу 15.10 в «Проект ERP»

1. Если проекта «Проект ERP» нет — завести его в справочнике проектов (экран проектов, тема та же, что у проекта MeetFlow).
2. Номер встречи 15.10 — 1 (по отчёту «Автоматический прогон — 15.10»), сверить в списке встреч.
3. Перенос вместе с задачами — новое действие администратора:
   `POST /meetings/1/move-project` с телом `{"project_id": <номер «Проекта ERP»>, "rebuild": false}`
   (заголовки как у экранов ERP: `X-Requested-With: erp-webapp`, `X-User-Id` суперадминистратора). `rebuild: false` —
   чтобы пересборка шла по порядку пункта 3, а не сразу очередью.
4. Проверить ответ: `from` — проект MeetFlow, `to` — «Проект ERP», `tasks` — число задач встречи 15.10 (было 13).
   У каждой задачи в истории строка «Перенесена вместе со встречей в проект «Проект ERP»».

## 3. Сразу пересобрать 26.10 и 15.10 по одной

- Модель — DeepSeek первой в цепочке генерации (как сейчас). Потолок — **0,15 $ на обе сборки вместе**.
- Сначала 26.10 (встреча 2, проект MeetFlow): кнопка «Собрать заново» или `POST /api/meetings/2/run`. Дождаться конца.
- Затем 15.10 (встреча 1, теперь в «Проекте ERP») так же. Повторных пересборок нет.
- После каждой — цена и число вызовов из журнала (`run_id`, `cost_usd`). Если после первой сборки потрачено больше
  0,10 $ — вторую не запускать, написать в отчёт.

## 6. Проект записи из общей папки — что изменилось для папки-приёмника

- Файл в подпапке, имя которой узнаётся в справочнике проектов (название или вариант, е = ё), идёт в этот проект;
  подпапка подпроекта — в подпроект.
- Файл в корне общей папки («Встречи по всем проектам» узнаётся как общая по названию) — в проект, названный в имени
  файла. Не назван — встреча с пометкой «проект не определён», карточка «Проект записи не определён» в «Разборе» с
  выбором проекта; сборка ждёт выбора. Распознавание и голоса идут сразу.
- Подпапка «Адресный учёт на складе» узнается, только если такой проект есть в справочнике. Сейчас проект один
  (MeetFlow) — новая запись из этой подпапки получит карточку выбора. Заводить ли проект — решение владелицы.
- Явно задать «общая / не общая» для папки проекта можно настройкой проекта `watch_folder_shared` (да/нет).
