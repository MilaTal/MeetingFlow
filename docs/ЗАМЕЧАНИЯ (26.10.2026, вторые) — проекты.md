## Что сделать (пунктом 1а — сразу после задания «модели, разделы, тестовая встреча», до пунктов 5–11)

1. **Справочник проектов** в MeetFlow — много проектов, ведётся вручную администратором («Проекты» в блоке администратора, как в Планёрке): название, варианты написания (для распознавания и поиска), активен/архив. У проекта — необязательные **подпроекты** (как в ERP), по умолчанию пусто. Без сидов с проектами компании.
2. **Встреча относится к проекту** (поле встречи; выбор при создании, можно сменить). Встреча без проекта допустима — «без проекта».
3. **Задачи и договорённости** — проект встречи по умолчанию, подпроект необязательный; проект задачи можно сменить вручную.
4. **Фильтр проекта** — всегда виден на реестре задач, договорённостях, списке встреч: первым пунктом «Все проекты» (без отбора — все записи, включая без проекта), ниже проекты, у выбранного — подпроекты, «без проекта».
5. **Поиск** без выбранного проекта — по всем записям; название проекта в строке поиска сужает до проекта (как в Планёрке), но записи без проекта при «Все проекты» не теряются.
6. **Подсказка модели и словарь распознавания** — названия и варианты активных проектов (как словарь проектов Планёрки, `slovar_whisper` — с пределом подсказки); определение проекта задачи по тексту — по справочнику (как в Планёрке), без жёсткого правила «только при прозвучавшем названии» (у Планёрки оно выключено).
7. «Истории проектов» отдельной вкладкой нет (убрана в обеих системах 25.10).
