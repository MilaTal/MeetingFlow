# Переключение проекта открывает «Реестр задач» (09.11.2026)

Слово владелицы 09.11.2026 (третий раз): «при переключении по проектам или при выборе общие встречи — должно
автоматически открываться со страницы Реестр задач. сейчас — не так».

## Что было не так

Правило 08.11.2026 (по скриншоту «куда-то потерялась задача») открывало при щелчке по проекту **«Реестр встреч»**. Слово
09.11 это отменяет: справа должен открываться **«Реестр задач»** (`#dashboard`) — задачи выбранного проекта или «Общих
встреч».

## Что сделано

- `app.js`, обработчик строки проекта и «Общих встреч»: вместо `#meetings` — переход на `#dashboard`;
- если экран уже «Реестр задач», hash не меняется (событие не сработает) — вместо этого `render()`, иначе на экране
  остались бы задачи прежнего проекта;
- статика `?v=20261109mf74` — нужен Ctrl+F5;
- тест `test_vybor_proekta_otkryvaet_vstrechi_0811.py` переписан под новое правило (в нём же закреплено, что «Реестр
  встреч» больше не открывается, и что при уже открытом реестре идёт перерисовка).

## Дополнено после проверки владелицей (09.11, второй заход)

Владелица: «всё ещё также — открывается не со страницы Реестр задач». Причина: экран реестра задач **не имел заголовка**
(правило 13.10 — «экран и так назван пунктом меню»), а в меню проекта не было пункта «Реестр задач»: после щелчка
подсвечивался проект, и понять, что открылся именно реестр задач, было нельзя — хотя таблица задач уже открывалась.

Сделано:

- **заголовок «Реестр задач»** с подписью «Задачи проекта, выбранного слева…» — теперь экран назван;
- в меню выбранного проекта пункт **«Реестр задач»** первым, со ссылкой `#dashboard`; текущий экран отмечен
  `aria-current="page"`;
- статика `?v=20261109mf75`.

Проверено в браузере: щелчок по проекту → `#dashboard`, заголовок «Реестр задач», меню проекта: «Реестр задач * /
Реестр встреч / Подготовка встречи / Договорённости по проекту / Статус проекта». Связанные наборы — **13 passed**.
