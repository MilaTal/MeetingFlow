# Самопроверка стенда одной командой (09.11.2026)

План, пункт 26. Вопрос «работает ли система и на текущем ли коде» до сих пор проверялся руками: wmic за PID, время
старта из журнала (в котором его не было), health, версии статики. Теперь — одна команда.

## Что проверяет `scripts/zdorovie.py`

1. **Служба 8005** отвечает и говорит `ok` (тема, busy).
2. **Код не новее запуска**: сравнивает `started_at` из `/health` с самой свежей правкой `.py` ядра и веб-слоя. Код новее
   — значит служба работает на старом коде, нужен перезапуск (код возврата 2).
3. **База**: `quick_check`, число людей и встреч (405 и 6 на сегодня).
4. **Журнал тени** существует — иначе 13.11 нечего считать.

Коды: 0 — всё в порядке; 1 — служба не отвечает; 2 — код новее запуска; 3 — база или журнал.

## Что для этого пришлось добавить

`GET /health` теперь отдаёт **`started_at`** — время старта процесса. Раньше в журнале обёртки времени старта не было
(строки uvicorn без даты), и «на каком коде работает служба» приходилось выяснять вручную.

## Прогон сейчас

```
Служба: ok, тема it_product, busy False
Код: служба на текущем коде (старт 09.11 05:28:47)
База: quick_check ok, людей 405, встреч 6
Журнал тени: строк 1
Итог: стенд в порядке
КОД=0
```

## Тесты

`tests/test_zdorovie_0911.py` — **5 passed**: старт из журнала (последняя строка), код новее запуска → «нужен перезапуск»,
запас 5 с на запись во время старта, самая свежая правка по каталогу, `/health` отдаёт `started_at`.

## Что это даёт

Перед каждой сборкой и 13.11 видно одной командой: служба жива, на текущем коде, база целая, журнал на месте. Если
перезапуск забыт — команда это скажет, а не придётся выяснять по числам замера.

Платных вызовов нет, рабочая база не менялась.
