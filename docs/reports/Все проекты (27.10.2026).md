# «Все проекты» (27.10.2026)

Первый шаг многопроектного слоя после справочника проектов: выбранный проект больше не обязателен для реестра задач,
встреч и договорённостей. Сделано по замечаниям «вторые — структура проектов», пункт 4.

## 1. Что сделано

- **Выбор проекта.** Внизу левой панели первым пунктом «Все проекты». Выбор запоминается; название системы вверху —
  «Все проекты».
- **Реестр задач.** `GET /api/projects/0/tasks?status=…` отдаёт задачи всех проектов (снятые по-прежнему не
  показываются), номер — свой в каждом проекте, в строке виден проект. Действия «Выполнено», «Вернуть»,
  «в оперативные» работают по номеру задачи, как раньше. Заголовок — «Реестр задач по всем проектам».
- **Встречи.** `GET /api/projects/0/meetings` — все встречи, добавлена колонка «Проект»; создание встречи при «Все
  проекты» скрыто (нужен конкретный проект).
- **Договорённости.** `GET /api/projects/0/agreements` — все решения, договорённости, вопросы и вехи; у строки виден
  проект; отборы по виду, состоянию и дате работают.
- **Остальные разделы** при «Все проекты» показывают «Выберите проект» с объяснением: подготовка встречи, план,
  команда, статус/сводка, поиск, параметры проекта. Глобальные экраны (модели, мониторинг, база голосов, разбор
  голосов, общая команда, проекты, оформление) работают как раньше.

## 3. Что не сделано и почему

| Пункт | Состояние |
|---|---|
| Поиск по всем проектам и сужение по названию проекта | нет: поиск пока требует выбранный проект; модуль поиска привязан к `project_id` в каждом запросе |
| «Сводка»/«Дорожная карта» по всем проектам | нет: считается по одному проекту |
| Смена проекта у задачи/договорённости вручную | нет: поле проекта у задачи не выводится в форме |
| Названия и варианты проектов в подсказке модели и словаре распознавания | нет: справочник и варианты есть, в prompt/словарь не подаются |
| Подготовка встречи и план при «Все проекты» | сознательно требуют проект: план строится по одному проекту |
