## 1. Цикл — каждые 15 минут, сам

Держи `/loop` с интервалом 15 минут. Каждый проход:

1. `git pull` ветки `dogonyaem-planerku`.
2. Найти новые записки — `docs/Для локальной машины MeetFlow — *.md` — которых нет в журнале (п. 3).
3. На каждую новую — **квитанция** за один проход: строка в журнал и push.
4. Работать по очереди: срочные (в имени «срочно») — первыми, затем по дате и по «заданию на день».
5. После каждого пункта — отчёт в `docs/reports/` и push сразу.
6. Нового нет — ничего не пушить.

## 2. Отчёты

- Отчёт — `docs/reports/<тема записки> (ДД.ММ.ГГГГ).md`. В начале — записка и её хэш, в конце — хэш коммита.
- Внутри:
  - HEAD и время запуска 8005, `/health`;
  - по каждому пункту: выполнено / частично / нет, с числами;
  - расход в $ и остаток потолка;
  - код и тесты;
  - что мешает.
- **Push — в GitHub `origin dogonyaem-planerku` (MilaTal/MeetingFlow).** Копия на P: — по желанию.
- Без ФИО, паролей и ключей; тексты с ФИО — в `Tests\` на P:.
- **Не угадывать причину.** Пропуск теста, ошибку, «нет пакета» — дословно из вывода (`pytest -rs`, текст исключения). Догадка помечается словом «предположение».

## 3. Журнал записок

`docs/reports/Журнал записок.md` — таблица: записка · хэш · получена · статус (в очереди / в работе / сделано / стоп) · хэш отчёта · примечание. Обновлять при каждом изменении статуса, push сразу.

## 4. Долгая работа

Пересборки и распознавание — строка в журнал и push не реже раза в час.

## 5. Стоп

Стоп и строка в журнал с причиной:
- потолок денег — две сборки подряд ставить только после цены первой;
- пустой ответ модели;
- ошибка;
- упавшие тесты;
- нужно решение владелицы.

Потом — следующая независимая записка.

## 6. Без слова владелицы — нельзя

- выдавать пароли;
- менять базу голосов;
- править код (только по записке, находка — в отчёт).
