# Для локальной машины MeetFlow — общая база контрагентов и проектов (28.10.26)

Задание владелицы 28.10.2026. В MeetFlow будут встречи с общей для компании тематикой. В них звучат проекты и внешние люди компании, которых нет в справочнике самого MeetFlow. Планёрка и Проект ERP этот справочник уже ведут, MeetFlow теперь берёт его оттуда же.

## Что сделано

Источник «общая база компании» — рабочая `app.db` Планёрки. Она открывается только на чтение (`mode=ro`), как при переносе ролей 27.10. В базу MeetFlow ничего не копируется, кроме двух настроек. Из Планёрки берутся:

- проекты из `projects`: название, варианты написания, площадки (`parent_id`) и цепочка договора. Снятые (`is_active = 0`) не берутся;
- люди из «Команды» (`users`), только подтверждённые и не снятые. Внешний даёт фамилию и организацию, свой сотрудник компании — фамилию, которая контрагентом не бывает. Неподтверждённые и безличные метки вроде «Участник 86» не берутся никогда, по правилу 24.10.

Свой справочник MeetFlow главнее. Проект Планёрки, чьё название или вариант совпали с проектом MeetFlow, не берётся, действует свой; код при названии считается вариантом написания. Площадка Планёрки, чей родитель есть в MeetFlow под тем же названием, становится подпроектом своего проекта MeetFlow. Человек Планёрки, чьё ФИО совпало с записью «Команды» проекта, не берётся.

Где используется:

1. Узнавание проекта записи. Свой справочник проект не узнал, а в имени подпапки или файла назван проект общей базы. Тогда встреча остаётся проекту папки, а не уходит в «проект не определён». Если названы два своих проекта, это спор, как раньше.
2. Укрупнение. Площадки общей базы — подпроекты своего родителя (основание «подпроекты»). Внешние люди и организации, в том числе из цепочек договора, — основание «один контрагент».
3. Подсказки. В словарь распознавания названия общей базы идут после своих, и при нехватке места отбрасываются первыми. В узкий вызов поручений идёт строка «Проекты компании (для написания названий, НЕ источник фактов)». Внешние контакты идут по тому же правилу, что свои внешние: полным именем — с пометкой «упоминать только там, где звучит», одним словом — только если прозвучал в этой встрече.

## Как включается

По умолчанию выключено: проект узкой тематики не должен получать в подсказку чужие названия. Предлагаю включать флагом у проекта, который ведёт встречи общей тематики, а не всем сразу. Флаг действует и на подпроекты.

| Настройка | Где | Что |
|---|---|---|
| `company_base_path` | общая | путь к `app.db` Планёрки; не задан — переменная окружения `MEETFLOW_COMPANY_BASE` |
| `company_topic` | у проекта | «встречи общей тематики компании» |
| `company_base_all` | общая | общая база всем проектам сразу, по умолчанию нет |

Нет пути или файл не открылся — общей базы нет, MeetFlow работает как раньше. Экранного переключателя нет: экраны MeetFlow — фронт ERP 1 в 1. Есть адреса для суперадмина и скрипт.

- `GET /api/settings/company-base` — состояние и числа по каждому проекту;
- `POST /api/settings/company-base` — путь, с повтором и паролем суперадмина, как база голосов;
- `POST /api/projects/{pid}/settings/company-topic` — `{"enabled": true}`;
- `POST /api/settings/company-base/all` — `{"enabled": true}`.

Каждое переключение пишется строкой в журнал решений.

## Шаги

1. `git pull --no-rebase origin dogonyaem-planerku`. Перезапуск через `run_dev`, `/health` 200.
2. Узнать путь к рабочей `app.db` Планёрки на этой машине. Обычно это `planerka\webapp\data\app.db` в папке монорепо, либо путь из `WEBAPP_DB_PATH` Планёрки. Копию базы не делать: читаем рабочую, только на чтение.
3. **Сухой ход.** Ничего не записывает, модели не вызывает:
   `python scripts/obshchaya_baza_2810.py --meetflow-db <рабочая meetflow.db> --planerka-db <app.db Планёрки> --project <номер проекта общей тематики>`
   В консоль выводятся числа: проектов и записей «Команды» в Планёрке, сколько проектов и площадок взято, сколько внешних, сколько с организацией, сколько своих сотрудников. Плюс первые названия проектов. ФИО не печатаются.
4. Проверка узнавания проекта записи, тоже без записи:
   `python scripts/obshchaya_baza_2810.py --meetflow-db <...> --planerka-db <...> --project <номер> --file "Башнефть/встреча 28.10.2026.m4a"`
   Ожидается: проект — номер проекта папки, «проект общей базы компании «Башнефть»». Взять 3–4 названия из Планёрки, которых нет в MeetFlow, и одно, которое есть, — у него должен узнаться свой проект.
5. **Применить** — тот же вызов шага 3 с `--apply`: путь и флаг проекта записываются в базу MeetFlow. Какой проект отмечать — решает владелица; без её слова не отмечать ни один.
6. Проверить в `GET /api/settings/company-base`: `ok: true`, у отмеченного проекта `enabled: true` и те же числа, что в сухом ходе.
7. Платной пересборки не делать. Подсказка поручений меняется только у отмеченного проекта, и проверится на ближайшей встрече общей тематики.
