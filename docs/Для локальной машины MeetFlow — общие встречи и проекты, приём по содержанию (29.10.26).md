# Для локальной машины MeetFlow — общие встречи и проекты, приём по содержанию (29.10.26)

Доработка 2 владелицы от 28.10.2026, коммит «Общие встречи и проекты, приём записи по имени и содержанию» в ветке `dogonyaem-planerku`. Статика — `20261028mf17`.

Что изменилось. Появились «Общие встречи» — служебный проект для встреч без проекта. Он заводится сам при запуске, стоит первой строкой, его нельзя переименовать, убрать в архив и удалить. Выбор проекта вверху левой панели стал блоком «Проекты», как в чатах: «Общие встречи», проекты, «Все проекты», внизу «+ Новый проект». У строки проекта — «…» с пунктами «Переименовать» и «Удалить». Удалённый проект не теряет встречи: они уходят в «Общие встречи» вместе с задачами. У встречи в «Реестре встреч» — «…» с пунктами «Переименовать», «Переместить в проект…», «Удалить». Удаление встречи с задачами снимает их с причиной «встреча удалена», и восемь секунд в уведомлении есть «Отменить».

Приём из папки-приёмника. Файл из папки проекта — сразу в проект, как было. Файл из общей папки сначала сверяется по подпапке и имени с названиями и вариантами проектов. Не узнан — после распознавания проект ищется по содержанию расшифровки: проект должен быть назван не меньше чем в трёх строках и хотя бы вдвое чаще второго. Узнан — встреча переносится туда, иначе остаётся в «Общих встречах», каждая запись — своей встречей. Если имя назвало один проект, а содержание уверенно другой, встреча остаётся по имени, оператору карточка «по имени и по содержанию разный». Причина раскладки видна подсказкой у «…» встречи. Прежняя карточка «Проект записи не определён» больше не открывается. Общая папка теперь ставится у «Общих встреч» на «Мониторинге RealTime», но прежняя настройка общей папки у проекта работает как раньше.

## Развернуть

1. `git pull --no-rebase origin dogonyaem-planerku`, сверить, что `HEAD` содержит коммит «Общие встречи и проекты, приём записи по имени и содержанию».
2. Перезапустить MeetFlow тем же способом, что обычно. Схема базы дополняется сама: поля `projects.general`, `projects.deleted`, `meetings.project_how`, `meetings.deleted_at`, `meetings.deleted_info`. Ничего руками не запускать.
3. В браузере — Ctrl+F5. В коде страницы должна стоять версия `20261028mf17` и строка `proekty.css`.

## Проверить кликами

Под суперадминистратором.

1. Блок «Проекты» вверху левой панели: первой строкой «Общие встречи», потом проекты, «Все проекты», «+ Новый проект». У «Общих встреч» нет «…».
2. «+ Новый проект» → «Проба 29.10», Enter. Проект появился и выбран. «…» → «Переименовать» → «Проба 29.10 два», Enter.
3. Выбрать любой рабочий проект, «Реестр встреч», у любой встречи «…» → «Переместить в проект…» → «Проба 29.10 два», «Сохранить». Встреча и её задачи — в «Проба 29.10 два». Протокол встаёт в очередь пересборки из готовой расшифровки — запись повторно не распознаётся.
4. В «Проба 29.10 два» у проекта «…» → «Удалить». В окне названо число встреч. После удаления встреча — в «Общих встречах» с задачами. Перенести её обратно в свой проект тем же «Переместить в проект…».
5. Удаление встречи проверять только на пустой пробной встрече, заведённой в «Подготовке встречи». На встречах с задачами не проверять: у них отмена восемь секунд, а задачи на это время снимаются.
6. Папка-приёмник: положить в общую папку копию расшифровки любой прошлой встречи с именем без названия проекта, например «Проверка приёма 29.10.2026.txt». Дождаться прохода. Ответ — куда легла встреча и что в подсказке у её «…». Автозапуск соберёт по ней протокол — одна сборка, около 0,02 $, это допустимо. После проверки удалить пробную встречу через «…» → «Удалить» и не отменять.
