# PROJECT_REPORT — скилл meeting-registry, 03.10.2026

## 1 Что сделано

Алгоритм Планёрки упакован в переносимый скилл и проверен по методике курса. Скилл — `skill/meeting-registry`:
SKILL.md, СЛУЧАИ.md с двенадцатью разборами, справочник контрактов и движок — эталонная реализация на
Python. Движок принимает запись совещания из папки без участия человека и проверяет вход. Модель
отвечает номерами строк, каждое её предложение проверяет код. Спорное разбирает агент, который сам выбирает
инструмент. Задачи и закрытия с цитатой ложатся в реестр, спорное — карточкой оператору. Целевая среда —
локальная Ollama, данные не покидают контур.

Паспорт агента — «03_Паспорт агента — meeting-registry (Р0–Р8).md» — пройден по десяти шагам курса. На
каждом шаге записаны сделанное, заглушки и риски, у чисел стоят метки «замер», «отнесение», «оценка».
Р7 целиком и Р8 собраны без материалов занятий 11–12, по критериям.

## 2 Десять шагов паспорта

Шаг 1 — цепочка из семи шагов, вердикты по пяти вопросам, три обоснованных отказа, ядро — шаги 2, 4, 5.
Шаг 2 — три точки контроля на шагах с последствиями, escalation с адресатом и сроком. Шаг 3 — таблица
отказов, три паттерна в коде, очередь, частичный отказ, сбой входа. Шаг 4 — запуск по событию в папке,
источник знаний и действие с записью, демо с прямым чтением базы. Шаг 5 — шесть потолков с источником
числа, cost-attack из трёх атак. Шаг 6 — sequential с валидаторами и агентским узлом, модель на шаг, пять
прогонов. Шаг 7 — As-Is на своих следах, узкое место — отсутствие реестра. Шаг 8 — To-Be с двумя
агентскими шагами из семи, четыре KPI с «до». Шаг 9 — режим по шагам, расчёт среды, compliance, scope
пилота. Шаг 10 — eval из 15 кейсов, два контрольных набора, регрессия трёх версий, мониторинг по шагам.

## 3 Архитектурные решения и почему

Модель отвечает номером, а не пересказом. Так цитата не может быть выдумана — приём Планёрки, закрытия 3
из 3 против 1 из 3.

Правило «всегда» живёт в коде. Отрицания, опора на строку, сверка людей, потолки, периметр проверяются
одинаково на любой модели.

Агентский узел только для спорного. Маршрут разбора спорного имени виден лишь в прогоне — это закрывает
позицию 4.2, на которой Планёрка стоит на единице. Потолок шагов проверяется до каждого шага, поэтому довод
Планёрки против агента снят.

Запасной путь — правила внутри периметра. Модель недоступна — протокол собирается правилами и честно
помечается. Отказ локальной модели не оставляет встречу без протокола.

Своё железо, а не API. По деньгам API дешевле в сотни раз, но тайна в данных: ФИО, содержание встреч,
голос. Решение — правило владельца, а не расчёт цены.

Журнал распределения по моделям — «05_Знания скилла/model_routing_history.md». Вся работа выполнена на
Claude. Роли манифеста сохранены: черновое чтение — субагенты Sonnet, ревью и уязвимости — отдельный
субагент без права правки.

## 4 Результаты тестов

Итерация 1, функциональные: модули, конвейер, клиент Ollama против поддельного сервера с тем же API,
папка-приёмник. Нашлись две ошибки — вход отклонял короткую встречу, выдуманное поручение на строке-отчёте
проходило проверки.

Итерация 2, безопасность модели: внедрение через реплику, модель, «послушавшаяся» внедрения, массовое
закрытие, подмена исполнителя агентом, выдуманный инструмент, cost-attack по шагам, деньгам и вызовам.
Нашлось, что признак «свершившееся действие» держался на конечном списке глаголов. Теперь он определяется
морфологией.

Итерация 3, устойчивость и нагрузка: пустой, двоичный, битый .docx, невидимые символы, превышение
контекста до первого вызова, восемь одновременных прогонов, шесть одновременных прогонов одной встречи,
поток из 100 встреч. Нашлось, что числа выпали из основ — из 300 задач заводилось 3.

Итерация 4, ревью ролью muse-glimmer: 16 воспроизведённых находок и одна по чтению, две критичные. На каждую
написан тест до правки, 24 из 25 упали. Все исправлены, одна — частично. Cost-attack нашёл ещё три
дефекта потолков, все исправлены.

Итерация 5, финальный прогон — `engine/eval/results/финальный_прогон.txt`. Тестов 118 из 118. Eval:
основной набор 15 из 15, живая речь 12 из 12, слепой 7 из 10. Пять прогонов — 4 из 5. Ложных записей в
реестре ноль на всех 37 кейсах. Cost-attack: потолок шагов сработал на 12-м шаге, денег — на 0,36 $ при
потолке 0,40 $, объёма — до первого вызова.

CI — только локальный раннер: Makefile и `.gitlab-ci.yml` с тегом `local`. GitHub Actions не используется.

## 5 Lessons learned

Первое. 15 из 15 с первого прогона — повод проверить прибор, а не радоваться. Пустой клиент провалил
типовые кейсы, значит судья работает. Но отложенный набор дал 8 из 12, а слепой после правок — 7 из 10.
Набор, по провалам которого правили, ничего не доказывает.

Второе. Правила держат точность, но не полноту. Ни одной ложной записи на 37 кейсах. Все провалы — пропуски
живой речи: «беру на себя», «нужно согласовать», поручение двоим. Полнота — работа модели, и это первое, что
мерить, когда она будет загружена.

Третье. Cost-attack проверяет потолок, а не модель. Все три атаки прошли на сценарном клиенте и нашли три
дефекта самих потолков. Ни один не был виден в 90 зелёных тестах.

Четвёртое. Независимый взгляд нашёл то, чего не видел автор. 16 находок ревью, ни одна не покрыта тестами. Две
— критичные, и обе из того же семейства, что и правила, ради которых всё строилось: подмена имени и
правило отрицаний.

Пятое. Защита от одной ошибки молча создаёт другую. Числа исключили из основ ради дат — и потеряли 297 задач
из 300. Порог проверяется с двух сторон.
