# Stakeholder deck — meeting-registry

Шесть слайдов по структуре критерия 8.1: проблема, как есть, как будет, метрики, rollout, стоимость. Числа
совпадают с паспортом. Текст — для заказчика, без названий узлов и библиотек.

## Слайд 1 Проблема

Задачи с планёрок живут одну-две встречи и теряются. Списка задач не было, протокол — час работы
секретаря каждый день. Сверка нашла 76 повторных записей в 44 группах: одну и ту же задачу ставили заново.

## Слайд 2 Как есть

Секретарь записывает встречу и ведёт заметки, после встречи сводит их в протокол, вручную подставляет ФИО и
рассылает. Отметить выполненное некуда. Пункты, которых нет в заметках, пропадают — 14 на одной встрече.

## Слайд 3 Как будет

Файл встречи кладут в папку. Через несколько минут готовы протокол и реестр: новые поручения с
ответственным и сроком, выполненные задачи закрыты с цитатой из встречи. Спорное — кто именно из двух
Марин, новый ли это человек — система не угадывает, а спрашивает ответственного одной карточкой. Голос и
текст встречи не покидают компанию.

## Слайд 4 Метрики

96 % закрытий задач делаются из протокола без ручного ввода (Планёрка). От текста до протокола — 2–4
минуты вместо часа. Ложных записей в реестре — ноль на 37 проверочных случаях. Полнота на живой речи без
модели — 7 из 10, цель с моделью — 9 из 10.

## Слайд 5 Rollout

Две недели в тени: система работает рядом с секретарём в копии реестра. Переход дальше — ноль ложных записей
и полнота не ниже 80 %. Две недели с проверкой каждого протокола. Переход — меньше одной правки на встречу и
не больше пяти карточек. Затем самостоятельная работа, оператор разбирает только карточки. Любая ложная
запись — шаг назад.

## Слайд 6 Стоимость

Через внешний API — 8–14 центов за встречу, около 2–3 $ в месяц. Внутри компании денег за вызов нет, но
нужен сервер с видеокартой на 24 ГБ — его цена главная статья, она ждёт ИТ. Выбор сделан не по цене, а
по правилу: данные встреч не выходят наружу.

## Ответ на вопрос «почему не оставить как есть»

Потому что без реестра задача живёт одну-две встречи. 76 повторов в 44 группах — это одни и те же задачи,
поставленные заново. С реестром 96 % закрытий делаются из протокола, и задача больше не теряется.

## Приложение — сценарий скринкаста до 5 минут

Первое окно — пустая база реестра, прямое чтение. Второе — папка-приёмник, в неё кладётся файл встречи.
Третье — консоль наблюдателя: файл забран сам, без нажатия. Четвёртое — база заново: появились задачи,
закрытие с цитатой, карточка «Марина — тёзки». Пятое — журнал прогона: какой инструмент выбрал агент на
каждом шаге. По желанию шестое — тот же файл повторно, задачи не задвоились. Материал для записи — папка
«07_демо».
