# Развёртывание meeting-registry — инструкция и требования к окружению

Документ для того, кто ставит движок на рабочую машину или сервер компании. Статус проекта на 04.10.26:
meeting-registry заморожен как эталон и набор проверок, основной инструмент — MeetFlow. Движок при этом
работает самостоятельно: принимает протокол или расшифровку совещания, ведёт реестр задач и очередь карточек
оператору.

## 1 Требования к окружению

Нужен Python 3.11 или новее, проверено на 3.13 под Windows 10. Ядро работает на стандартной библиотеке.
Три пакета из «requirements.txt» необязательны: pymorphy3 даёт морфологию русского языка, без неё основы слов
грубее, python-docx нужен для чтения .docx, pytest — для тестов. Без них движок не падает, а деградирует мягко
и называет причину.

Модель нужна только для режима с моделью. Это Ollama на этой же машине или на сервере внутри периметра
компании. Без модели движок работает на правилах, ключ `--model heuristic`. Голос и тексты совещаний не
уходят за периметр: движок отказывается работать с адресом модели вне localhost, если адрес не внесён явно в
MR_ALLOWED_HOSTS. Модели, обучающиеся на присланных данных, запрещены кодом.

Под базу и протоколы достаточно 100 МБ. База — один файл SQLite, сервер баз данных не нужен. Видеокарта
нужна только Ollama и только для крупных моделей.

На Windows консоль должна печатать в UTF-8, иначе кириллица в выводе ломается. Перед запуском выполнить
`set PYTHONIOENCODING=utf-8` в cmd или `$env:PYTHONIOENCODING="utf-8"` в PowerShell.

## 2 Установка

```bash
git clone https://github.com/MilaTal/MeetingFlow
cd MeetingFlow/meeting-registry/skill/meeting-registry/engine
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m pytest tests -q
```

Последняя команда — проверка установки. На 04.10.26 ожидается «119 passed». Если тестов меньше или есть
падения, развёртывание не продолжать.

## 3 Команда проекта

Движок сверяет исполнителей с «Командой». Это JSON-файл со списком людей: ФИО, отдел, роль, варианты имени.
Образец с вымышленными людьми — «07_демо/команда.json». Для рабочего проекта файл составляется заново из
настоящего состава. Персональные данные в репозиторий не кладутся, файл команды держится рядом с базой.

## 4 Запуск

Разобрать одну встречу:

```bash
python -m meeting_registry process "Протокол 02.10.md" --date 2026-10-02 --db реестр.db --team команда.json --model heuristic
```

Следить за папкой-приёмником, без человека: каждый новый файл разбирается, протокол сохраняется сразу.

```bash
python -m meeting_registry watch "Папка-приёмник" --db реестр.db --team команда.json --interval 60
```

Очередь карточек оператору и журнал прогонов — шаги, токены, стоимость, ошибки:

```bash
python -m meeting_registry cards --db реестр.db
python -m meeting_registry runs --db реестр.db
```

Чтобы работать с моделью, ключ `--model heuristic` заменяется именем модели в Ollama, например
`--model glm-4.7-flash`. Адрес Ollama задаётся MR_OLLAMA_URL.

## 5 Переменные окружения

Все переменные необязательны, значения по умолчанию подобраны по замерам Планёрки.

| Переменная | По умолчанию | Назначение |
|---|---|---|
| MR_OLLAMA_URL | http://127.0.0.1:11434 | адрес Ollama |
| MR_MODEL | пусто | модель, если не задана ключом `--model` |
| MR_ALLOWED_HOSTS | пусто | разрешённые адреса модели сверх localhost, через запятую |
| MR_TIMEOUT | 300 | секунд на один вызов модели |
| MR_NUM_CTX | 32768 | окно контекста модели |
| MR_MAX_CALLS | 14 | потолок вызовов модели на прогон |
| MR_MAX_STEPS | 12 | потолок шагов агента |
| MR_MAX_CHARS | 48000 | потолок знаков на вызов |
| MR_CHUNK_CHARS | 12000 | размер куска длинной записи |
| MR_MAX_CHUNKS | 10 | потолок кусков (около двух часов совещания) |
| MR_MAX_COST_USD | 0.40 | денежный потолок прогона, только для платной модели |
| MR_MAX_SECONDS | 1200 | потолок времени прогона |
| MR_MAX_ARTIFACTS | 40 | потолок задач и карточек за прогон |
| MR_PRICE_IN, MR_PRICE_OUT | 0 | цена за миллион токенов, для учёта стоимости |

При достижении любого потолка прогон останавливается, а не продолжает молча. Причина видна в `runs`.

## 6 Проверка после развёртывания

Тесты, три набора eval и атака на стоимость запускаются из папки engine:

```bash
python -m pytest tests -q
python eval/run_eval.py --label проверка --set cases
python eval/run_eval.py --label проверка --set cases_live
python eval/run_eval.py --label проверка --set cases_blind
python eval/cost_attack.py
```

Прогон на демо без модели. Демо-записи уже разобраны и лежат в «обработано», поэтому их копируют в новую
папку — так демо остаётся нетронутым:

```bash
mkdir demo_in
copy "..\..\..\07_демо\Папка-приёмник\обработано\*.txt" demo_in
python -m meeting_registry watch demo_in --db демо.db --team ../../../07_демо/команда.json --model heuristic --once
python -m meeting_registry runs --db демо.db
```

Ожидается два прогона со статусом done. Проверено 04.10.26.

## 7 Что не входит в репозиторий

Папка «00_промежуточные» — выгрузки сессий и тексты курса: в них встречаются ключи доступа и чужие материалы.
Не входят записи совещаний, файлы .env и ключи. Письма между ветками и журналы проверки входят, в них есть ФИО
сотрудников. Поэтому репозиторий на GitHub должен быть закрытым.
