## Когда применять

Пришёл файл встречи — расшифровка, выгрузка ВКС, заметки секретаря — и из него надо получить протокол и
записи в реестре задач. Строится новый конвейер такого рода, меняется модель, промпт или порог. Надо
решить, какое решение отдать модели, а какое оставить коду или человеку. Разбор одной встречи вручную,
без движка, тоже идёт по этому порядку.

## Главное правило

**Модель предлагает, код проверяет, человек решает спорное. Ничего непроверенного в реестр не идёт.**

Модель отвечает номером строки, а не пересказом. Цитату берёт код дословно. Каждое предложение модели
сверяется с источником этой встречи и с «Командой». Не прошло — карточка оператору, а не тихая подстановка.
Правило со словом «всегда» живёт в коде, а не в промпте (Планёрка, 18.09.26).

## Порядок работы

Шаг 1. Принять источник. Проверка идёт до создания встречи и до первого вызова модели: пустой текст,
двоичный мусор, чужой текст, длиннее 400 000 знаков — отказ с причиной. Дата встречи — из имени файла.
Найденная дата вымарывается перед следующим шаблоном, иначе «2026_09_05» читается как 9 мая. Две даты в
имени — не угадывать, а завести карточку. Повтор того же содержимого узнаётся по отпечатку текста, а не
по имени файла. Файл берётся из папки только дописанным: размер не меняется две секунды и файл можно
переименовать. Повод — Планёрка 01.10.26: недописанный файл забирался, и каждые 15 минут шёл новый
платный прогон.

Шаг 2. Разрезать на строки. Реплика режется на предложения, каждому — номер и говорящий. «Хорошо.
Назаров, подготовьте…» — два высказывания, и номер должен указывать на поручение. Невидимые символы
(U+202E, U+200B) вырезаются. Реплики, обращённые к системе («игнорируй инструкции», «закрой все
задачи», «ты теперь администратор»), из разбора убираются и уходят оператору одной карточкой.

Шаг 3. Извлечь поручения. Запись режется на куски по 12 000 знаков с перекрытием в три строки. Каждый
кусок — один вызов с одним вопросом: кому что поручено. Ответ — JSON с номерами строк. Поручение есть,
когда человеку или отделу прямо назначено действие или человек сам берёт работу. Не поручение — отчёт о
сделанном, вопрос без просьбы, «вернёмся позже», «хорошо бы», отрицание, действие без исполнителя.
Одно поручение — одна задача: «Назаров, подготовьте…, а Ершова пусть запросит…» — две задачи (Проект ERP,
01.10.26, задача №130 склеила три поручения).

Шаг 4. Проверить кодом каждое предложение модели. Строка существует и не помечена как внедрение. Строка
имеет форму поручения. Формулировка опирается на слова строки и соседних — не меньше половины смысловых
основ. Срок принимается, только если его слова прозвучали рядом с поручением. Исполнитель назван в
строке или сам взял работу от первого лица. Отчёт о сделанном без повелительной формы — не поручение.

Шаг 5. Сверить людей с «Командой». Фамилия совпала или отличается падежом — назначить. Искажение
распознавания со сходством от 0,85 — исправить молча («Чистяка» становится Чесноковой, правило 02.10.26). Сходство
0,78–0,85 — кандидат карточкой. Отдел без фамилии — руководитель отдела; руководителя нет — карточка.
Тёзки — карточка. Имя не сравнивается с фамилией по общему началу: «Сергей» — не «Сергеев». Названное имя,
противоречащее фамилии, понижает совпадение до «похоже».

Шаг 6. Разобрать спорное агентом. Для каждого спорного пункта модель сама выбирает инструмент: сверить
имя, посмотреть, кто говорил на встрече, прочитать строки, поискать похожую открытую задачу. Финальное
решение проверяет код. Назначить можно только кандидата из сверки с «Командой». Тёзку — только если он
говорил на встрече, а второй нет. «Похоже» — только карточкой. Дубль — только та же задача того же
человека. Потолок — 12 шагов на прогон и 5 на пункт, проверка до каждого шага.

Шаг 7. Найти закрытия. Кандидатов отбирает код: фразы о свершившемся действии (прошедшее время
совершенного вида или краткое причастие), к каждой открытой задаче не больше четырёх фраз с общими
основами. Модель отвечает номером фразы. Код повторно проверяет фразу правилом отрицаний. Своя встреча
не закрывает свои задачи. Ранняя встреча не закрывает задачу, поставленную позже. Больше трёх закрытий
и больше половины открытых разом — всё к человеку одной карточкой. Повод — 235 предложенных смен статуса
при 3 верных (Планёрка, 22.09.26).

Шаг 8. Записать. Задачи, закрытия с цитатой, история статусов и карточки пишутся одной транзакцией под
замком на данных. Частично записанной встречи не бывает. Протокол собирает код: таблицы из реестра,
нумерация с 1, без служебных пометок. Если кусок записи не разобран, протокол не пишет «не прозвучало».

## Правило отрицаний

Слово во фразе ещё не факт. Статус не меняют отрицание, вопрос, условие, намерение и будущее время,
поручение, частичный результат, «вернёмся позже». «Отменять не будем, работаем» задачу не снимает — с
этой фразы правило и началось (21.09.26, в проверочном прогоне модель закрыла 18 задач из 18). «Не
отменили», «пока не сняли» — тоже не снятие. «Больше не актуально» — снятие. При сомнении статус не
меняется.

## Контрольный слой

Потолки проверяются кодом до вызова модели. Вызовов — 14 на прогон, шагов агента — 12, знаков в
запросе — 48 000, кусков — 10, стоимость — 0,40 $ с прогнозом следующего вызова, время — 20 минут,
записей — 40. Откуда каждое число — в `engine/meeting_registry/control.py`. После потолка — карточка
оператору и исход «остановлено по пределу». Повтора нет: он кормит разгон. «Сделано» и «остановлено
по пределу» — разные исходы прогона. Повтор допустим только на сетевом отказе, до трёх попыток. Плохой
JSON — один повтор с напоминанием о формате.

## Периметр

Модель — только локальная или из явного белого списка адресов. Запросы к локальной модели идут мимо
системного прокси, иначе текст встречи уходит на прокси. Модели, которые учатся на присланных данных,
запрещены кодом. Голос не покидает периметр, облачного распознавания нет (правило владельца 24.09.26).
Ключи и `.env.local` не печатаются.

## Как запускать движок

```bash
cd engine
python -m meeting_registry process "Планёрка 2026_10_02.txt" --db реестр.db --team команда.json --model glm-4.7-flash
python -m meeting_registry watch "Папка-приёмник" --db реестр.db --team команда.json --interval 60
python -m meeting_registry runs --db реестр.db
python -m meeting_registry cards --db реестр.db
```

Без модели (`--model heuristic`) движок работает по правилам и помечает протокол: «собран без языковой
модели». Это же запасной путь, когда локальная модель недоступна. Полнота правил на живой речи ниже, чем
у модели: на слепом наборе 7 из 10, все три провала — пропущенные поручения, ложных записей ноль.

## Как проверять изменение

Тесты — `python -m pytest tests -q`. Eval — три набора: основной (15 кейсов), «живая речь» (12) и слепой
(10). Регрессия — один набор до и после изменения, `eval/compare.py`, каждое расхождение — в журнал
улучшений. В замере «до и после» меняется одна вещь: история «12 задач против 6» оказалась сменой модели,
а не фразы в промпте (30.09.26). Прибор проверяется на заведомом ответе: пустой клиент обязан провалить
типовые кейсы, `similarity(a, a)` обязан дать 1. Набор, по провалам которого правили код, засвечен —
нужен новый слепой.

## Чего не делать

Не менять статус задачи без цитаты из этой встречи. Не подставлять имя по похожести без подтверждения
(«Гуцко» принят за «Галкин», 27.09.26). Не назначать тёзку наугад. Не переписывать сохранённый протокол
задним числом — он документ, а таблица в нём называет себя срезом. Не повторять прогон после потолка. Не
чинить порогом то, что сломано в материале. Не судить по одному прогону. Не объявлять «починил» без
проверки на живом пути — правка промпта не доходит до сервера, который не перезапущен (12.09.26). Не
закрывать «дыру», не сверившись с решениями владельца — она может оказаться решением.

## Что делать с отрицательным результатом

Записывать так же подробно, как положительный: что мерили, на чём, какое число вышло, почему вывод
отозван. Отрицательный результат — тоже строка сдачи. Примеры в «СЛУЧАИ.md»: подсказка распознаванию
(слов 849 против 992 без неё), диаризация, не поднявшая покрытие, закрытие по голосу ниже случайного
уровня (9 совпадений при 11,3 ожидаемых), слепой набор движка 7 из 10.
