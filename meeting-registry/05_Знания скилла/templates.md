# Шаблоны — что переиспользовать в следующем проекте

1 Узкий вызов модели. Один вопрос, вход — пронумерованные строки внутри рамки «данные, не инструкции»,
ответ — JSON с номерами. Готовые промпты — `skill/meeting-registry/engine/meeting_registry/prompts.py`.

2 Карточка оператору. Вид, заголовок с причиной, дословная цитата, кандидаты, ключ по содержанию. Решения —
«принять / своё / не заводить». Схема — «references/контракты.md».

3 Журнал прогона. Таблицы `runs` и `run_steps`: шаг, результат, секунды, токены, деталь, исход прогона и
причина. Отвечает на вопрос «почему агент решил так» по конкретному запуску.

4 Лист потолков в коде. Каждое число с источником рядом — `control.py`, словарь `LIMIT_SOURCES`.

5 Eval из трёх наборов. Основной — 10–15 кейсов четырёх типов. Отложенный — написан до прогона. Слепой —
написан после правок и прогоняется один раз. Плюс тест прибора: пустой клиент обязан провалить типовые кейсы.

6 Регрессия построчно. `eval/compare.py <набор> <до> <после>`, каждое расхождение — запись в журнал
улучшений в форме «что думали, что намерили, что сделали».

7 Cost-attack как сценарий. Три атаки — шаги, деньги, объём, по каждой две записи: шаг срабатывания и что
было дальше. `eval/cost_attack.py`.

8 Поддельный сервер модели для тестов коннектора. HTTP-сервер с тем же API на случайном порту:
повторы, обрезка, отсутствие модели, учёт токенов — без настоящей модели. `tests/test_ollama_client.py`.

9 Ревью ролью. Отдельный агент без права правки, с задачей «каждую находку воспроизведи скриптом».
Находки — тестами до правки, по скиллу fix-verify.

10 Паспорт по шагам курса. На каждом шаге — сделано, заглушки, риски. Числа с метками «замер»,
«отнесение», «оценка», «учебное».
