# Письмо 02 — два решения владельца для MeetFlow

03.10.26. От ветки meeting-registry ветке MeetFlow. Оба пункта — прямые решения владельца в этой сессии,
не наши предложения.

## 1 Снятие задачи по голосу — делать, как для единиц

Решение владельца: «снятие по голосу нужно, пусть делают как для единиц».

Сейчас конвейер ставит только DONE (pipeline.py:336). DROPPED выставляется только вручную через web
(app.py:310-325), а «не актуальн» стоит в блокерах отрицания (negation.py:281). Поэтому «больше не
актуальна» фактом не становится.

Образец — закрытие единиц: units.py:395-449, `closed_how="голос"`, «Вернуть» после. Предлагаемые
условия — по вашему же замеру из units.py:177-181, где 8 из 10 голосовых закрытий были «подтвердили»:

| условие | почему |
|---|---|
| Снятие — только по явным словам снятия: «снимаем», «сняли», «отменили», «отменяем», «больше не нужно», «не актуально», «не требуется» | подтверждение и обсуждение задачу не снимают |
| Отрицание перед глаголом снятия — не снятие: «не отменили», «пока не сняли», «отменять не будем» | у вас это уже верно, проверено нашим прогоном; не потерять при правке |
| «Больше не актуально» вынести из блокеров отрицания в признак снятия | иначе снятие голосом не сработает никогда |
| Цитата берётся кодом, фраза проходит тот же отбор кандидатов, что и закрытие | одинаковый путь для DONE и DROPPED |
| Ранняя встреча не снимает задачу, поставленную позже; своя встреча не снимает свою | как для закрытий, см. письмо 01, п. 3 |
| Массовое снятие — карточкой, вместе с закрытиями | см. письмо 01, п. 2 |
| «Вернуть» — как у единиц, история с цитатой | ошибка снятия должна быть обратимой одной кнопкой |

Проверочные фразы — наш тест `tests/test_review_fixes.py::test_negated_drop_is_not_drop` и
`test_units.py::test_negation_rule` в «Создать скилл_markdown\skill\meeting-registry\engine».

## 2 Разбор спорного имени по участникам встречи — нужен

Решение владельца: агент, который сам выбирает инструмент, как самоцель не нужен. Нужен один механизм —
разбор спорного имени: посмотреть, кто говорил на встрече, прежде чем отдать карточку.

Достаточно правила в коде, без агента и без вызова модели — это дешевле и проверяемо.

Шаг 1. Team.find вернул несколько кандидатов (тёзки, «Марина» при двух Маринах).

Шаг 2. Собрать говорящих этой встречи: подписи реплик в расшифровке, имена из выгрузки ВКС, имена из
базы голосов, если она подписала реплики.

Шаг 3. Из кандидатов говорил ровно один — назначить его. Говорили двое и больше или никто — карточка, как
сейчас. В карточку добавить строку «на встрече говорил: …», чтобы оператору было из чего выбрать.

Шаг 4. «Похоже, но не уверенно» (искажённая фамилия ниже порога автоправки) и человек не из «Команды» —
только карточкой, говорящие здесь не помогают.

Предел честный. При локальном Whisper без дикторов (asr_whisper.py:79 пишет «Говорящий:») говорящих нет,
и правило не срабатывает — остаётся карточка. Оно работает на выгрузке ВКС и на записях, где база
голосов подписала реплики.

Образец кода и теста у нас — `meeting_registry/agent.py::_spoke` и проверка в `_final` для статуса
ambiguous. Тесты — `test_review_fixes.py::test_ambiguous_assign_without_evidence_refused`, eval-кейсы P5,
P6 и B9 в `eval/cases.json` и `eval/cases_blind.json`. Агентский цикл из нашего движка переносить не нужно.
