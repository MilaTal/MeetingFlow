## Документы чистые: системных пометок в документе нет

Правило владельца 13.10.26 для всех систем. Протокол, план, сводка, выгрузки реестра и все выгрузки в Word — документы
для пользователя. Системных сообщений в них нет. Версии и сборки никто не ищет и не сверяет: это делает код проверки
до того, как документ попадёт к человеку.

Куда уходит то, что раньше попадало в документ: находка проверки — в карточку «Конфликтов» или в «Технические
сообщения», ход сборки — в путь планёрки у администратора. Сам документ ради этого не правится. Строка состояния
над документом («собран … · пересобран …») — только у администратора, у рабочей группы её нет.

Файл общий для Планёрки и ERP. Сторож каждой системы читает формы ниже и проверяет собранный протокол и выгрузки в
Word: ни одна форма не должна найтись. Ловятся формы пометок, а не отдельные слова: «Искитим принял с замечаниями»
и «сборка мебели завершена» — деловой текст, его сторож не трогает. Перед добавлением формы прогоните её по
настоящим протоколам базы: совпадений в деловом тексте быть не должно.

### Формы пометок

Одна строка — одно регулярное выражение (Python, без учёта регистра) в обратных кавычках.

- `Говорящ\w*\s*\d+(?!\d)(?!\.\d)` — безымянная метка голоса в любом падеже («Говорящему 3»), только с номером
- `SPEAKER_\d+` — метка разделения по голосам
- `Участник\w*\s*\d+(?!\d)(?!\.\d)` — безымянная метка участника ВКС в любом падеже, только с номером; после номера нет точки с цифрой — «участниками 13.08.26» это дата (ERP, 13.10.26)
- `Голос\w*\s*\d+(?!\d)(?!\.\d)` — метка голоса («Голос 3», «Голосу 1»), только с номером: фамилия «Голосов» без номера не метка
- `(?<![\d:])\d{1,2}:\d{2}:\d{2}(?![\d:])` — тайм-код записи
- `строк[аи]\s+записи` — номер строки записи
- `[\w\-]+\.(?:docx|txt|md|json|mp4|m4a|wav|mp3|webm|ogg)\b` — имя файла
- `пересобран` — пометка о пересборке
- `собран\s+(?:из|\d{2}\.\d{2})` — строка «собран … из …»
- `с замечаниями проверки` — вердикт проверки
- `проверяющ\w*\s+модел` — упоминание проверяющей модели
- `черновик\w*\s+протокол` — упоминание черновика протокола
- `модель\s+(?:вернула|предложила|не\s+ответила)` — ход сборки
- `отложено\s+оператору` — замечание сборки
- `взяты\s+из\s+таблицы\s+протокола\s+кодом` — замечание сборки
- `имя\s+говорящего\s+по\s+второй` — замечание сборки
- `верси[яи]\s+(?:протокола|сборки|\d)` — пометка о версии
- `сборк[аиеу]\s+(?:протокола|не\s+удалась|прервана)` — пометка о сборке
- `пометк[аи]\s+внедрени` — пометка внедрения
- `\(не в «Команде проекта»\)` — пометка сверки с «Командой» (ERP)
- `пропущен[аы]?\s+\d+\s+встреч` — счётчик пропусков (ERP)
- `Неопознанный участник` — безымянный участник (ERP)
- `статус не прозвучал` — пометка о статусе (ERP)
- `Полный аудит открытых задач` — служебный раздел (ERP)
- `\(в записи\s*\d{1,2}:\d{2}\)` — короткий тайм-код записи (ERP; голый «(15:10)» сюда не входит — так выглядит время встречи)
- `пока не в реестре|в реестр не вносим|не заведена в реестр` — пометка о реестре (ERP)
- `по заметкам\s*—[^|\n]{0,60}по расшифровке` — сверка источников (ERP)
- `Для плана пока нет основы` — служебная заглушка плана (ERP)
- `намеренно опущен` — служебная пометка (ERP)
- `раньше\s+даты\s+постановки` — пометка о сроке (владелец 13.10.26, Б5: в документе голая дата)
- `(?m)^\s*(?:\*\*[^*\n]+\*\*\s*[—–-]\s*)?(?:по\s+[^\n.]{1,40}\s+)?новой\s+информации\s+нет\.?\s*$` — строка «без новостей» (владелец 13.10.26, Б3)
- `(?m)^\s*\*\*[^*\n]+\*\*\s*[—–-]\s*(?:информация\s+не\s+прозвучала|не\s+обсуждал(?:и|ось|ась)?|сроки?\s+не\s+озвучен[аоы]?|не\s+озвучен[аоы]?|статус\s+не\s+прозвучал)\.?\s*$` — объект без новостей (Б3)
- `задача\s+с\s+(?:план[её]рки\s+)?\d{2}\.\d{2}\.\d{2,4}` — заметка секретаря в формулировке задачи (Б4)
- `не\s+обсуждал\w*\s+на\s+текущей\s+план[её]рк` — заметка секретаря в формулировке задачи (Б4)

### Хвосты секретаря в формулировке задачи

Заметки секретаря для себя, которые модель переносит в формулировку задачи дословно (владелец 13.10.26, Б4: протокол
секретаря 30.09, задача №219). Код вырезает их при любом заведении и правке задачи; вырезанное — в журнал, без
карточки; если после вырезания формулировка пустая, остаётся как была. «поставлена дд.мм.гггг» в документе — данные
(Б1), но в самой формулировке это хвост: дату постановки дописывает код при выводе.

- `[,;]?\s*\(?\s*задача\s+с\s+(?:план[её]рки\s+)?\d{2}\.\d{2}\.\d{2,4}\s*\)?` — «задача с 29.09.2026», «(задача с 26.08.2026)», «задача с планёрки 28.09.2026»
- `[,;]?\s*не\s+обсуждал\w*\s+на\s+текущей\s+план[её]рке` — «не обсуждали на текущей планерке»
- `(?m)[,;]?\s*поставлена\s+\d{2}\.\d{2}\.\d{2,4}(?=[ \t]*(?:\||$))` — «поставлена 30.09.2026» только хвостом: в конце формулировки или ячейки таблицы; «задача поставлена 06.08.26, ответственный…» в прозе — не хвост (ложное срабатывание у ERP, Сводки №15–16)
- `[,;]?\s*\(?\s*статус\s+не\s+прозвучал\w*\s*\)?` — «статус не прозвучал»

### Чего здесь нет

Пометки, которые несут смысл для читателя, — это данные, не системные сообщения. Срок «сегодня (дд.мм.гггг)» остаётся
(владелец 12.10.26). Решения владельца 13.10.26 по описи Планёрки 13.10 14-50: дата постановки «поставлена дд.мм.гггг» в документе
остаётся (Б1, 9 pt серым курсивом по решению 09.10.26); «не указан» и «не назначен» — данные (Б2); «(оценка)» у срока
— данные (Б5).
