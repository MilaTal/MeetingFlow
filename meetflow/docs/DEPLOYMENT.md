# Развёртывание MeetFlow

Документ — для того, кто ставит MeetFlow на машину и запускает его для проекта. Что делает система — в `README.md` и `docs/ARCHITECTURE.md`. Что ещё ждёт решения оператора — в `OPERATOR_TODO.md`.

## 1. Требования к окружению

| Что | Требование | Комментарий |
|---|---|---|
| ОС | Windows 10/11 | Проверено. Linux и macOS должны работать: код без привязки к ОС, есть `scripts/run_tests.sh`; сценарий запуска для них — `python -m meetflow serve` (раздел 4) |
| Python | 3.11 и новее | Проверено на 3.13 |
| Память | от 4 ГБ | Для локального распознавания и Ollama — по требованиям моделей |
| Диск | от 1 ГБ под код и базы | Модели Whisper и Ollama — отдельно, от 3 до 20 ГБ |
| Порт | один свободный, по умолчанию 8002 | На машине владельца 8000 и 8001 заняты Проектом ERP и Планёркой: сервер на них не стартует |
| Сеть | исходящий HTTPS до `openrouter.ai` | Только при подключении OpenRouter. Локальному подключению сеть не нужна |
| Браузер | современный (Chrome, Edge, Firefox) | Интерфейс без сборки, открывается по адресу сервера |
| GPU | не обязателен | Ускоряет локальное распознавание записей (faster-whisper); без него — на процессоре |

Обязательные пакеты Python — в `pyproject.toml`: fastapi, uvicorn, pydantic, python-docx, python-multipart, httpx. Необязательные:
- `morph` — pymorphy3: признак выполнения по форме глагола; без него остаётся список слов;
- `voice` — faster-whisper и imageio-ffmpeg: распознавание аудио и видео; без них записи ждут, текст и docx принимаются;
- `test` — pytest.

## 2. Установка

```bash
git clone https://github.com/MilaTal/MeetingFlow
cd MeetingFlow/meetflow
python -m venv .venv
.venv\Scripts\activate
pip install -e ".[test,morph]"
```

Для распознавания записей добавьте `voice`: `pip install -e ".[test,morph,voice]"`. Модели Whisper скачиваются один раз; после этого работа офлайн (`HF_HUB_OFFLINE=1` ставит сценарий запуска).

Проверка установки — все тесты должны пройти:

```bash
python -m pytest tests -q
```

## 3. Подключение модели

**Модели по умолчанию нет** (правило владельца 13.10.26 для ERP, Планёрки и MeetFlow; ответ владельца 15.10.26). Модель каждой роли — генерация, проверка, распознавание, необязательный досмотр — назначает супер-администратор в «Моделях». Пока роль не назначена, она «не настроена»: вызовов нет, чужая роль не подставляется, сборка встречи не начинается, оператору карточка. Одно исключение — как в ERP и Планёрке (решения владельца 09.10 и 13.10.26): проверка без своей точки идёт на модель черновика, и это показано явно — в «Моделях», на мониторинге и в сведениях о прогоне: «модель черновика: <точка>» и «отдельная модель проверки не назначена». «Не настроена» у проверки — только когда не назначено ни то, ни другое.

| `MEETFLOW_LLM` (или `-Llm`) | Что это | Что нужно |
|---|---|---|
| не задана, `routes` | маршруты из «Моделей» (`data/models.json`) | ничего: при первом запуске кладётся справочник заготовок без адресов и ключей — DeepSeek, Claude по ключу, OpenRouter, локальная qwen, Whisper, свой код распознавания, сервис распознавания. Супер-администратор заполняет заготовку, проверяет связь и ставит её в роль |
| `mock` | стенд без модели | только явно; на каждом экране плашка «Стенд без модели», прогоны не входят в стоимость |
| `openrouter` | модели через OpenRouter | модели — в теме `llm.openrouter.*` (по умолчанию пусто — «не настроена»), ключ `OPENROUTER_API_KEY` |
| `ollama` | локальная модель | Ollama на `http://localhost:11434` (иначе `OLLAMA_URL`) и модели в теме `llm.generator` / `llm.verifier` (по умолчанию пусто) |

Функции точки — общий модуль ERP и Планёрки (`meetflow/connectors/shared/`, копии байт в байт): ключ значением, введённый в «Моделях», хранится в `model_keys.local.json` рядом с `models.json` (вне git), наружу — только «ключ задан · …XXXX»; рассуждение модели у точки (как у модели / low / high / выключено); потолок ответа у точки; тариф и предел расхода в месяц по поставщику; у Claude не передаются `temperature` и `top_p`; внешняя точка ходит через системный прокси; отказ 401/403 — с ответом поставщика, ключ вычищен.

**Распознавание речи** (уточнение владельца 15.10.26 — единообразно с ERP). Только на своей машине или в сервисе внутренней сети: точка роли «Распознавание речи» с внешним адресом отклоняется при загрузке `models.json` и при записи из «Моделей». Три типа подключения: «Whisper на этой машине» (faster-whisper: модель — имя или путь к папке, устройство auto/cuda/cpu), «Свой код распознавания на этой машине» (функция «модуль:функция», папка с кодом) и «Сервис распознавания во внутренней сети» (POST wav, ответ JSON с текстом; форма запроса raw или multipart). Роль не назначена — запись ждёт с причиной «распознавание не настроено». Очередь — одна запись за раз на машину, общая с ERP и Планёркой: файл `recognition_lease.json` рядом с базой голосов (путь к базе — в «Настройках»; явно — `RECOGNITION_LEASE_PATH`); пока распознаёт другой продукт, запись ждёт в папке-приёмнике и берётся на следующем проходе; очередь видна в «Мониторинге RealTime». Папку-приёмник, частоту обхода и базу голосов задаёт только супер-администратор.

Для всех подключений:
- потолок ответа — 4096 токенов на вызов (`llm.max_answer_tokens`), у точки — свой, если задан;
- модели «contributor», которые обучаются на присланном, запрещены;
- голос и записи наружу не уходят никогда — распознавание только локальное;
- через OpenRouter уходит текст встречи, с запретом провайдерам хранить и обучаться (`data_collection: deny`).

**Ключ OpenRouter.** Положите его в файл `.env.local` в корне репозитория одной строкой `OPENROUTER_API_KEY=...`. Файл в `.gitignore`. Сценарий запуска берёт ключ сначала из переменной окружения, затем из этого файла; запасной путь — `.env.local` Планёрки. Значение нигде не печатается.

## 4. Запуск

Windows:

```powershell
powershell -ExecutionPolicy Bypass -File scripts\run_dev.ps1 -Theme erp_rollout -Port 8002 -Db data\project.db -Llm openrouter
```

Любая ОС:

```bash
python -m meetflow serve --theme erp_rollout --db data/project.db --port 8002      # модели — в «Моделях»
```

Откройте `http://127.0.0.1:8002`. В «Мониторинге» видно, какой инструмент модели выбран, какие модели работают и задан ли ключ.

**Сеть.** Сервер стартует только на `127.0.0.1`: входа по паролю пока нет, роль выбирается на экране. На внешнем адресе `serve` откажется запускаться. Открывать сервер в сеть — только после входа по паролю (`OPERATOR_TODO.md`, п. 1).

**Остановка.** Ctrl+C в окне сервера. Если окно закрыто, а порт занят — остановите процесс-владельца порта: остановка фоновой задачи не всегда гасит uvicorn.

## 5. Первый проект

1. **Тема.** Скопируйте `themes/it_product.json` в `themes/<id>.json`. Заполните словарь, разделы протокола, роли, палитру и `prompts.domain_role`. Проверьте заглушки: `python -m meetflow todo --theme <id>` — каждая должна быть решена осознанно.
2. **Проект:** `python -m meetflow new-project "Название" --theme <id> --db data/<id>.db`.
3. **Запуск** — по разделу 4 с `-Theme <id> -Db data\<id>.db`. В левом нижнем углу выберите роль «Супер-админ».
4. **«Команда».** Свои — фамилия и имя полностью; внешние — организация и роль. Похожего человека форма не заведёт молча — спросит «тот же или новый?».
5. **«Настройки».** Папка-приёмник записей (адрес вводится дважды, меняется только с этой машины), интервал опроса, автозапуск протокола, путь к базе голосов.
6. **Первая встреча.** Загрузите расшифровку или заметки на экране встречи и нажмите «Сформировать протокол». Или положите файл с датой в имени в папку-приёмник.

## 6. Данные и резервные копии

- База проекта — один файл SQLite в `data/`: реестр, встречи, протоколы, карточки, «Команда».
- Журнал вызовов модели и прогонов — `data/logs/*.jsonl`.
- Папка `data/` в `.gitignore`: в git данные не попадают.
- Резервная копия — копия файла базы при остановленном сервере.
- Записи (аудио, видео) после распознавания удаляются; храним только текст.

## 7. Проверки и обновление

- Все тесты: `make test` или `scripts\run_tests.ps1`. Отдельно безопасность: `-m security`; нагрузка: `-m "load or scale"`.
- Наборы проверки ветки meeting-registry: `eval/README.md`. На заглушке они меряют заглушку; полнота — только на модели.
- CI — только локальный: `scripts/run_tests.*`, `Makefile`, `.gitlab-ci.yml` для локального раннера. GitHub Actions запрещён манифестом проекта.
- Обновление: `git pull`, затем тесты, затем перезапуск сервера.

## Маршруты моделей (09.10.26)

Третий инструмент подключения — `MEETFLOW_LLM=routes`. Модели не задаются переменными: у роли генерации и роли
проверки — цепочка именованных точек в `data/models.json` (путь — `MODEL_ROUTES_PATH`). Первая доступная обслуживает
вызов; точка, которая не ответила (нет связи, 5xx/429 после повторов, нет ключа или денег, модели нет на сервере),
выводится на `cooldown_sec`, и вызов уходит на следующую. Ошибка запроса и оборванный ответ не переносятся. Виды точек:
`openrouter`, `openai` (свой OpenAI-совместимый сервер — LM Studio, Ollama `/v1`), `ollama` (родной протокол;
удалённый адрес — только с `"allow_remote": true`). Формат файла тот же, что у Планёрки и ERP. Образец —
`docs/models.example.json`.

Переключение без перезапуска: поменять порядок в `roles` или `python -m meetflow routes use generate <точка>`.
`python -m meetflow routes show` — файл, `routes check` — короткий запрос на каждую точку обеих ролей.
Проверено 09.10.26 живым прогоном на OpenRouter: недоступная главная точка → переход, переключение на другую модель и
возврат, проверка на своей цепочке — 5 из 5.
