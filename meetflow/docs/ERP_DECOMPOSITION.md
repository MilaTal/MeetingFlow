# Этап 1. Декомпозиция исходных проектов: ядро, коннекторы, конфигурация

Источники разбора. Три сессии владельца («Meeting protocol 02.07.26», «Meeting protocol 2_planerka», «Planerka: ошибки и git в webapp», вместе около 680 МБ переписки, из которой извлечено 6,5 МБ диалога и прочитано целиком 12 агентами-конспектами). Код Проекта ERP (`ITMO_case\Рабочая папка проекта ERP project\webapp`, 29 сервисов, 451 тест) и Планёрки (`ITMO_planerka\webapp`, 46 сервисов, около 1040 тестов) прочитаны отдельно, чужой код не менялся. Конспекты лежат в `_intermediate/digests/`.

Главный вывод. Обе ветки выросли из одного скилла `meeting-protocol` и независимо пришли к одной архитектуре: источник встречи → узкие вызовы модели → проверки кодом → независимая проверка → реестр → карточки человеку. Различаются они тематикой (ERP-внедрение против ежедневной планёрки) и входами (заметки и транскрипт против записи с голосами). Это и есть граница «ядро / коннектор / конфигурация».

## 2. Что было специфично и куда ушло

Специфика ERP: «Отдел ОТН по умолчанию» (отменено владельцем 12.09), роль «аналитик 1С:ERP 2.4», стадии внедрения 1С, План встречи из «триады источников», Дорожная карта и Сводка. Во framework это тема `erp_rollout`: словарь, разделы протокола (включая «Риски внедрения»), уменьшительные имена команды, потолок 20 вызовов / 2 $, палитра индиго.

Специфика Планёрки: блоки протокола секретаря («Ключевые показатели», «Поступления ТМЦ», «Планирование ВО»), коды отделов, роль «Директор», ведущий-директор, эталон секретаря. Во framework это тема `daily_ops`: разделы, роль `director`, руководители отделов как `PLACEHOLDER`, палитра «тёмный лес».
