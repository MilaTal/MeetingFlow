# CONNECTOR_SPEC — контракты коннекторов

Ядро знает только абстрактные классы из `meetflow/connectors/base.py`. Любой коннектор — подкласс одного из пяти типов, с уникальным `name` в своём `kind`.

| Тип (`kind`) | Метод | Вход | Выход | Базовые реализации |
|---|---|---|---|---|
| `source` | `read(data, filename)` | байты файла | `SourceDoc` | `text` (.txt .md), `docx` |
| `asr` | `transcribe(path)` | путь к записи | `SourceDoc(transcript)` | `whisper_local` |
| `vision` | `describe(data, filename)` | байты изображения | `SourceDoc(other)` | `ollama_vision` |
| `llm` | `complete(system, user, json_mode, temperature, purpose, deadline)`, `worst_call_usd(prompt_chars)` | промпт | `LLMResult` | `ollama`, `openrouter`, `mock` |
| `output` | `render(markdown, title)` | markdown | байты файла | `md`, `docx` |

Папка-приёмник (`FolderIntake`) — вспомогательный коннектор входа: она находит файлы и передаёт их в `Pipeline.ingest`.

## Общие обязательства

1. **Понятные ошибки.** Отказ — `ConnectorError` с фразой для человека («Файл пустой», «Формат не поддерживается»). Трассировка на экран не уходит.
2. **health()** проверяет соединением, а не флагом (урок мониторинга Планёрки). Для LLM — наличие модели в Ollama.
3. **Локальный контур.** LLM и Vision отказываются работать с нелокальным адресом без явного `allow_remote=True`. ASR — только офлайн (`HF_HUB_OFFLINE=1`, `local_files_only`), облачные клиенты запрещены.
4. **Особые префиксы ошибок ASR.** `waiting_tools:` — инструменты не установлены, запись ждёт; `held_recording:` — длительность вне окна темы. Конвейер превращает их в карточки, запись не теряется.
5. **SourceDoc.meta** заполняется: `connector`, для текста — `reply_share`, `ambiguous`, `own_output`.

## Адаптация под целевые локальные модели

Профили в `core/prompts.py`:

| Профиль | Модели | Особенности формата |
|---|---|---|
| `glm` | GLM-5.3, GLM-5.3-Flash, GLM-4.7-Flash | длинный контекст, function calling (`supports_tools`), JSON-подсказка в system |
| `deepseek` | DeepSeek, DeepSeek-R | вырезание `<think>…</think>`, короче кусок |
| `qwen` | Qwen3 | суффикс `/no_think`, вырезание рассуждений |
| `generic` | прочие | консервативный контекст 32 тыс. знаков |

`num_ctx` в Ollama задаётся явно: по умолчанию 8192, и длинный системный промпт не помещался (ERP 11.09). Точные значения — `PLACEHOLDER` в теме, их подтверждает оператор.

## Два инструмента подключения модели (решение владельца 03.10.26)

Выбор делается при развёртывании переменной `MEETFLOW_LLM` или параметром `scripts\run_dev.ps1 -Llm`:

| Значение | Инструмент | Модели | Что нужно |
|---|---|---|---|
| `mock` | стенд без модели | — | ничего; на каждом экране плашка, прогоны не входят в стоимость |
| `ollama` | локальная модель (`llm_ollama`) | `llm.generator`, `llm.verifier` темы — пока заглушки | Ollama на localhost и имена моделей |
| `openrouter` | OpenRouter (`llm_openrouter`) | `llm.openrouter.generator / verifier` — по умолчанию как в Планёрке: `qwen/qwen-plus` и `meta/muse-spark-1.3` | `OPENROUTER_API_KEY`; `run_dev.ps1` берёт его из `.env.local` Планёрки, если переменная не задана |

Общее для обоих:
- потолок ответа `llm.max_answer_tokens` = 4096 (решение владельца 03.10.26);
- обрыв по потолку — понятное сообщение без повтора;
- 4xx не повторяются;
- `deadline` прогона ограничивает таймаут и паузы;
- модели «contributor» запрещены.

У OpenRouter ещё три правила:
- `provider.data_collection: deny`;
- рассуждение выключено (у Muse — включено с `exclude`, иначе 400);
- `worst_call_usd` по ценам из открытого каталога: потолок прогона не пускает вызов, худший случай которого не помещается в остаток.

## Мультимодальность

Изображение (доска, скан) идёт в Vision и превращается в **материал** (`SourceKind.OTHER`), а не в источник фактов. Задача из описания картинки не заводится: у неё нет дословной цитаты в тексте встречи. Аудио и видео идут в ASR и становятся расшифровкой.
