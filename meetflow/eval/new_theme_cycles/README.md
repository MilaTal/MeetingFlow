# Прогон «новая тематика по скиллу meetflow»

Циклы проверки раздела «Новая тематика на MeetFlow» скилла meetflow: тема, «Команда», маршруты моделей, две встречи
с ожиданиями, записанными до прогона, сверка числом. Первый прогон — 09.10.26 на машине разработки, модели через
OpenRouter; итог и найденные дефекты — СЛУЧАИ.md скилла, случай 13.

1 Что здесь

- `cycle1_stroyka.json` и `cycle2_sklad.json` — тематики «Стройплощадка» и «Склад» с ожиданиями. Они засвечены: по
  их провалам 09.10.26 правили код MeetFlow, и их 18 из 18 и 16 из 16 ничего не доказывают. Годятся как
  регрессия — после правки всё ещё проходят?
- `cycle3_agro__ОТЛОЖЕННЫЙ.json` — тематика «Агрохолдинг». Отложенный набор: написан 09.10.26 после правок, ни разу
  не прогонялся и не открывался при них. Он и меряет то, что проверяется, — другую модель, локальный контур.
- `themes/` — темы трёх тематик; перед прогоном скопировать нужную в `themes/` репозитория.
- `cycle_run.py` — проект, «Команда», встречи через HTTP стенда; `cycle_check.py` — сверка с ожиданиями.

2 Печать отложенного набора

- `cycle3_agro__ОТЛОЖЕННЫЙ.json` — f1c1c84d9a2f718461fd151b880fb1063cc690549626eac7854419fdb39d54f4;
- `themes/agro.json` — ad3766139aeac0c349da5fc529de22beb5a1f1837dbf063f0704eb7baac6f330.

Сумма не совпала — набор менялся, и его результат перестаёт быть отложенным. После первого прогона он тоже
засвечивается: при правках по его провалам нужен следующий свежий набор.

3 Как прогнать

1. Скопировать тему: `copy eval\new_theme_cycles\themes\agro.json themes\`.
2. Маршруты в `data/models.json` — точки локальных моделей основными.
3. Стенд в режиме маршрутов на свободном порту: `scripts\run_dev.ps1 -Theme agro -Port 8022 -Llm routes -Db data\agro.db`.
4. `python eval\new_theme_cycles\cycle_run.py eval\new_theme_cycles\cycle3_agro__ОТЛОЖЕННЫЙ.json 8022`.
5. `python eval\new_theme_cycles\cycle_check.py eval\new_theme_cycles\cycle3_agro__ОТЛОЖЕННЫЙ__итог.json`.
6. Погасить стенд по владельцу порта, удалить тему из `themes/` и базу стенда.

10.10.26 владелец изменила правило отдела без руководителя: исполнитель пустой, отдел только в карточке. Если
в запечатанном наборе ожидание ставит отдел в графу исполнителя — это ошибка ожидания по изменённому решению, а не
дефект; показать отдельной строкой отчёта, печать при этом не пересчитывать.

Каждое «НЕТ» разобрать до правки: ошибка ожидания (форма слова в ключе, решение владельца), ошибка прибора или
дефект. Ожидания задним числом не подгонять — исправление ожидания показывать отдельной строкой отчёта, как в
цикле 2. Расход и время каждой встречи — из отчёта прогона.
