# meetflow-project

> Копия. Источник — `~/.claude/skills/meetflow-project/SKILL.md` (установлен 03.10.26). Любое изменение вносится сразу в обе копии — см. раздел «Изменение самого скилла».

Framework — репозиторий `meetflow-framework` (на машине владельца — папка `ITMO_project lead`). Ядро не правится под тематику: тематика — JSON-тема, внешнее — коннектор.

## Порядок работы

1. **Тема.** Скопировать `themes/it_product.json` в `themes/<id>.json`. Заполнить `vocabulary` (как называются встреча, протокол, реестр), `protocol_skeleton` (разделы протокола этой тематики), `notes_markers` (слова, по которым узнаются заметки секретаря), `roles`, `design.palette`, `prompts.domain_role`. Проверить: `python -m meetflow todo --theme <id>` — все `PLACEHOLDER` должны быть осознанными.
2. **Команда.** Завести людей с фамилией и именем полностью. Уменьшительные имена — в `people.diminutives`, руководители отделов — в `people.department_heads`. Ничего не угадывать: неполное упоминание человека всегда уходит карточкой.
3. **Модели.** В `llm.generator` и `llm.verifier` — разные семейства локальных моделей в Ollama, с явным `num_ctx`. Облачные провайдеры не подключать. Модели с суффиксом `contributor` запрещены.
4. **Потолки.** `budget`: вызовы, деньги, знаки, время. Потолки не выключать и не завышать ради прохождения атаки.
5. **Проверка.** `bash scripts/run_tests.sh` или `scripts\run_tests.ps1`; затем `python -m meetflow demo --theme <id>` и сервер на свободном порту (не 8000/8001).

## Правила, которые держат проект (не нарушать)

- Источник фактов — только текст встречи. Справочники — для написания имён, не для фактов.
- Модель называет номер строки, цитату берёт код. Статус задачи из встречи меняется только по цитате, прошедшей правило отрицаний.
- Заметки — акцент, а не предел. Расхождение источников показывается, а не примиряется.
- Непроверенное не идёт в рабочие материалы: кандидат — карточкой.
- Протокол сохраняется сразу; проверка — после и справкой.
- Ответ оператора становится правилом после двух одинаковых ответов.
- Голос и данные не покидают периметр.
- Мерить числом, а не глазом. Свою гипотезу о починке проверять до правки. Прибор врёт чаще продукта.
- Тест, закреплявший прежнее решение, переворачивают, а не удаляют.
- Проверки задачи стоят на любом пути её заведения (протокол, единицы встречи, что появится дальше), иначе второй путь их обходит.
- Меру похожести проверяют на парах с известным ответом до правки — и свою, и чужую. Порог Жаккара не отличает «то же самое» от «то же, кроме главного слова».
- Неточный механизм не расширяют, пока он не прошёл замер (закрытие по голосу, разделение по голосам). Подтверждение решения — не закрытие.
- Поиск по сырой речи — решение о доступе. Его задают владельцу тематики (`search.raw_speech`), а не включают по умолчанию.

## Новый коннектор

Подкласс из `meetflow/connectors/base.py`, регистрация в `PluginRegistry` или строка `"модуль:Класс"` в `connectors.extra` темы. Обязательно: понятная `ConnectorError`, `health()` соединением, локальный адрес. Образец и тест — `docs/PLUGIN_GUIDE.md`, `tests/test_robustness_load.py::CsvSource`.

## Готовность проекта к запуску (чек-лист)

- [ ] `todo` пуст или все заглушки подтверждены оператором
- [ ] тесты зелёные, включая `-m security` и `-m "load or scale"`
- [ ] пять прогонов на реальных встречах на локальных моделях, записана стоимость успешного результата
- [ ] прогон всех встреч темы по порядку дат на пустом реестре с настоящей моделью: сколько встреч собрано без сбоев, цена за встречу, совпадение с рабочим реестром (у Проекта ERP — 20 из 20, 0,03–0,17 $; стенды с выключенной моделью этот замер не заменяют)
- [ ] строка «кто закрывает задачи»: доля закрытий по записи встречи и доля закрытий человеком (у ERP — 1 из 101 по записи; иначе очередь оператора недооценена)
- [ ] перед включением закрытия по голосу — слепая разметка двумя агентами по одному определению, без ответов механизма, и сравнение со случайным уровнем
- [ ] сервер стенда гасится по владельцу порта: остановка фоновой задачи не гасит uvicorn (находка ERP)
- [ ] атаки А, А-2, Б, В прогнаны с боевыми потолками
- [ ] экран проверен на двух ширинах (1280 и 1500+), не больше пяти размеров шрифта
